# Plano simples — Conteúdo e banners

> Execução direta com `executing-plans`, conforme fluxo autorizado. Somente módulo 7; entregar e aguardar depuração.

**Objetivo:** administrar banners WebP e publicar os elegíveis em home/sobre por páginas e API públicas, mantendo o frontend existente de identidade.

**Fontes:** RF18/RF19/RF23/RF24, UC11–UC12, CT22–CT23, RN14 e Q10/Q12/Q15. Responsável autorizou desenvolver o módulo 7. Pergunta opcional sobre administração exclusiva/publicação pública/período/ordem enviada; contrato inicial abaixo é escolha para depuração até resposta diferente.

**Arquitetura:** app `conteudo`, modelo `Banner`, serviço compartilhado, seletores administrativos/públicos, telas simples e APIs DRF. Pillow 12.3.0 validará bytes WebP. SQLite e arquivos locais sob MEDIA_ROOT, sem servir diretório media diretamente. Branch `feat/conteudo`, base `631c00f`.

## Contrato

- Apenas administradores de negócio/superusuários ativos consultam/manipulam cadastros completos. Visitantes consultam somente publicados. Sessão/CSRF na administração; token de integrador não autentica gestão.
- `titulo` obrigatório até150, `texto_alternativo` opcional até250 (publicação usa título se vazio), `banner_img` WebP obrigatório na criação, `status` ativo/inativo/agendado, `local` home/sobre, `ordem` inteiro0–2147483647 padrão0; empates por ID. Aparar textos. Vários por local; sem rearranjo automático.
- `inicio_exibicao`/`fim_exibicao` ambos obrigatórios no agendado, com fuso e fim posterior; UTC normalizado. Ativo/inativo exigem período vazio para evitar semântica ambígua. Interface Brasília; API timestamps ISO8601 com fuso. Elegibilidade: ativo ou agendado com início<=agora<fim; excluídos/inativos ocultos.
- WebP real decodificado com Pillow, estático, até5MiB e4096x4096; PNG/arquivo renomeado/truncado/animado rejeitados. Nome armazenado UUID, não nome fornecido. Limites/alt e restrição a estáticos são escolhas técnicas do MVP.
- `versao` inicial1; edição, substituição, desativação e exclusão exigem versão, UPDATE condicionado; conflito409 `versao_desatualizada`. Exclusão lógica (`excluido_em`) remove da administração/publicação. Sem restaurar/excluir fisicamente neste módulo.
- Validar dados/arquivo antes de escrever. Novo arquivo gravado antes da persistência; erro/CAS perdido remove apenas esse arquivo novo. Imagens anteriores preservadas em substituição/exclusão, para não apagar arquivo em uso. Reter/limpar arquivos históricos é política futura. Sem eventos de auditoria adicionais não solicitados.
- Administração `/banners/`, `novo/`, `{id}/`, `{id}/editar/`, `{id}/excluir/`. GET exclusão confirma, POST executa com CSRF/versão. Lista paginada25; links só admin.
- API `/api/v1/banners/`, `/{id}/`: GET/POST/PUT/PATCH/DELETE; DELETE JSON com versão retorna204; criação/substituição multipart com `banner_img`, sem base64/URL de imagem. Demais alterações JSON; campos desconhecidos/ID/versão inicial/exclusão arbitrária proibidos. PUT exige campos cadastrais; imagem preservada se omitida em edição.
- API pública `GET /api/v1/publico/banners/?local=home|sobre`, local obrigatório, paginada25; somente `{id,titulo,texto_alternativo,imagem_url,local,ordem}` de elegíveis. Páginas públicas `/publico/` e `/publico/sobre/` exibem imagens por local; sem alterar `/` privado. Página renderiza todos os elegíveis ordenados, sem carrossel elaborado.
- Imagem `/banners/{id}/imagem/`: admin vê cadastros ativos mesmo não publicados; demais só elegíveis, senão404. Resposta WebP/nosniff/no-store. Nenhum endpoint fornece caminhos privados. Páginas/API públicas e imagens sem cache para respeitar mudanças/período a cada pedido; administração privada no-store.
- Fora: conversão automática, links externos/carrossel, publicação em site externo, CDN/cloud/implantação, recuperação/limpeza automática de arquivos, banco de produção.

## Foco da revisão

1. URL de imagem de inativo/agendado fora do período/excluído não publica mídia ou metadados para visitante; preview exige administrador.
2. Arquivo renomeado/truncado/animado/grande nunca persiste; CAS ou falha de banco limpa apenas upload novo, sem apagar arquivo antigo/vencedor.
3. Publicação exatamente no início/fim, fusos equivalentes e status sem período respeitam regra única em HTML/API/imagem.
4. Multipart versus JSON não enfraquece versão/ordem/campos protegidos; comum/staff/inativo/token não mantêm banners.
5. Nome/ordem empatados, páginas vazias, substituição e exclusão concorrentes não misturam metadados nem expõem excluídos.
